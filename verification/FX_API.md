# 阶段四：公开汇率 GET 接口的真实依据

新增端点：`https://hq.sinajs.cn/list=fx_susdcny`，不需要 Cookie、账户或 API Key。
使用在岸 USD/CNY（每美元对应的人民币），不是 USD/CNH 离岸人民币，也不是银行现钞买卖价。
本次请求在 2026-10-14 执行，先取得响应并核对新浪官方页面脚本，之后才编写 Swift 解析。

## 实际 curl

```bash
curl -H 'Referer: https://finance.sina.com.cn' 'https://hq.sinajs.cn/list=fx_susdcny'
```

实际 HTTP 头和 GB18030 原始响应保存在 `fixtures/stage4/fx-headers.txt` 和 `fx.gb18030`，转为 UTF-8 后如下：

```text
var hq_str_fx_susdcny="23:33:01,6.6980000000,6.6988000000,6.6928000000,100.0000000000,6.6935000000,6.7014000000,6.6914000000,6.6988000000,在岸人民币,0.0896,0.0060,0.0100,此行情由新浪财经计算得出,0.0000,0.0000,,2026-10-14";
```

## 原始字段核对

| 索引 | 解析用途 | 实际字段 |
| --- | --- | --- |
| parts[0] | 来源时间（北京时间） | 23:33:01 |
| parts[3] | 昨收，仅用于核对 | 6.6928000000 |
| parts[8] | 当前 USD/CNY，用于金价换算 | 6.6988000000 |
| parts[9] | 品种名称，仅用于核对 | 在岸人民币 |
| parts[17] | 来源日期（北京时间） | 2026-10-14 |

新浪官方页面：https://finance.sina.com.cn/money/forex/hq/USDCNY.shtml
页面引用的脚本：https://n.sinaimg.cn/finance/forex_n/getData_20241021.js?v=20241021
官方 SDK：https://finance.sina.com.cn/sinafinancesdk/js/sf_sdk.js

核对 SDK 的 forex 分支：fx_ 品种使用日期索引 17，时间索引 0，price 使用索引 8。没有使用买卖报价，也不照搬 SDK 在零价时回退昨收的行为。
原始响应中 parts[2] 恰好也为 6.6988，不能仅凭本次相等就认定它是当前价；映射依据是官方脚本。
Swift 源码旁保留实际响应注释；不把执行返回的 JavaScript 作为代码运行，只解析数据字符串。

## 失败降级

网络/HTTP/解码/字段解析失败立即标记汇率为 stale，旧汇率只保留在服务缓存用于诊断，不再用于显示溢价。
来源时间或最后成功时间达到五分钟、明显在未来、无效数字、非正数、乘法溢出都不用于溢价计算。
每个失败源使用共享 RetryPolicy 指数退避，上限一分钟；上一轮未结束跳过新请求。
原五个行情接口的 URL、参数、SKU、请求头及 Provider 源码逐字未变。

## 公式独立复算

用 Python Decimal 核对：国内 885 元/克、伦敦金 4100 美元/盎司、USD/CNY 6.6988：

- 国际折算价约 883.022167923224 元/克。
- 差额约 +1.977832076776 元/克。
- 差额 / 国际折算价 × 100，约 +0.223984419488%。
- 展示为 `溢价 +1.98 元/克（+0.2%）`。

把差额代回国内价，再乘 31.1035、除以汇率，可反算回 4100；百分比代回可恢复国内价 885。
这些数字是明确的测试输入，不是伪装的实时行情；UI 仅显示实际接口数据。
